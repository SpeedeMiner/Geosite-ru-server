# Синхронизация исключения Habr

До разделения каналов Server использовал только стабильные номерные релизы Light, поэтому
изменение только в Light `latest-optimized` не попадало в Server
автоматически. Сервер получил такое же исключение отдельно, по решению
[Light PR №44](https://github.com/SpeedeMiner/Geosite-ru-light/pull/44).

В `RU` не входят `habr.com`, его поддомены и охватывающий их суффикс
верхнего уровня. `habrastorage.org`, корень `domain:ru` и все остальные
правила сохранены. Проверенная дельта к Server v11.21 — **4 507 → 4 506**
правил, только `−domain:habr.com`. Остальные protobuf-записи совпадают
побайтно. Проекция из номерного Light v11.21 с новой политикой совпадает
с повторной проекцией из Light `latest-optimized` после удаления Habr.

SHA-256 нового Server DAT —
`0ddfe436d683ef803ca2cafba3736322a2c6390d50f30ba77f88ffbf15cbb83d`.

Номерной `v11.21` оставлен историческим снимком. Правка была
опубликована в `latest-optimized` и ветке `release` отдельным
исключением с проверенной парой SHA-256. Теперь плавающий канал читает
Light `latest-optimized` напрямую, а номерные снимки по-прежнему
независимы и не перезаписываются. Исключение Habr сохраняется в постоянной серверной политике. С 25 ноября 2026 года изменения покрытия относительно предыдущего снимка только протоколируются и не блокируют публикацию.
